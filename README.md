# 감정 판단 실습실

**스토리라인 예시를 따라가고, 평가 요소를 직접 바꾸면서 감정 후보가 어떻게 갱신되는지 확인하는 도구**입니다.

메인 화면에는 세 가지 예시와 `스토리 따라가기` / `직접 실습` 버튼이 있습니다. 실습에서는 감정과 평가 요소를 노드와 선으로 표시하고, 공유 근거를 연결된 모든 감정에 동시에 반영합니다.

> 공통된 4개 요소는 두 감정 모두를 지지하므로, **그 결과만으로 Frustration이 더 높다고 판단할 수는 없습니다.** 동률이면 두 후보를 구분하는 미확인 요소를 확인해야 합니다. 점수는 동작을 보여주기 위한 **‘해당 항목 수’ 예시**이며, 실제 감정 판정 점수는 별도로 설계·검증해야 합니다.

## 스토리라인 예시

### 1. Anger와 Frustration — 공통 근거만으로는 이동하지 않기

교육용 가상 대화입니다. 내려간 눈썹을 영상에서 확인했다고 가정합니다. 실제 영상은 포함되어 있지 않습니다.

> A: “왜 자꾸 제출이 안 돼?”  
> B: “서버 오류래. 설정만 바꾸면 다시 보낼 수 있대.”  
> **Target · A: “마감 직전인데 자꾸 막히네. 설정부터 바꿔볼게.”**

| 확인 순서 | 평가 내용 | Anger / Frustration | 후보 처리 |
| --- | --- | --- | --- |
| 초기 예측 | Anger라고 가정 | 0 / 0 | Anger에서 시작 |
| 공통 근거 확인 | 목표 불일치·높은 통제 가능성·수단적 문제·내려간 눈썹 → 해당 | **4 / 4** | 동률이므로 이동 보류 |
| 구분 근거 확인 | 상황·사건 중심 → 해당 / 타인에게 원인 귀속 → 비해당 | **4 / 5** | Frustration을 다음 후보로 제안 |
| 후보 이동 | 확인한 근거를 유지 | 4 / 5 | Anger → Frustration |

**직접 해보기:** `상황·사건 중심`을 해당으로 바꿔 Frustration으로 이동한 뒤, `타인에게 원인 귀속`·`고함`·`비난하는 발화 내용`을 해당으로 바꿔 보세요. 다른 해석을 가정했을 때 Anger로 돌아갈 수 있는지 확인합니다. 모든 조작은 가설 검토이며 실제 관찰을 새로 얻는 것은 아닙니다.

### 2. Fear에서 Sadness로 — 무엇의 불확실성인지 확인하기

사용자가 제공한 면접 불합격 대화입니다. 대화문만 있으며 인물의 영상·음성은 없습니다.

> A: “면접 결과 나왔어?”  
> B: “응. 또 떨어졌어.”  
> A: “아.. 이번에는 정말 기대했는데.”  
> **Target · B: “괜찮아, 뭐. 익숙한 일이잖아.”**

| 확인 순서 | 평가 내용 | Fear / Sadness | 후보 처리 |
| --- | --- | --- | --- |
| 초기 예측 | Fear라고 가정 | 0 / 0 | Fear에서 시작 |
| 공통 근거 확인 | 목표 불일치·상황·사건 중심 → 해당 | **2 / 2** | 후보 유지 |
| 통제 가능성 검토 | 근거 부족 → 미확인 | 2 / 2 | 점수 유지 |
| 결과 확인 | 이번 면접 결과의 확실성 → 해당 / 불확실성 → 비해당 | **2 / 3** | Sadness를 다음 후보로 제안 |
| 후보 이동·추가 검토 | 동기 종류·표정·음성은 미확인 | 2 / 3 | Fear → Sadness, 잠정 판단 |

평가 대상은 **이번 면접 결과**입니다. 미래의 취업에 관한 불안까지 부정하는 것은 아닙니다. A의 “기대했는데”를 B의 생각으로 옮기지 않습니다. Neutral 가능성도 남겨 둡니다.

### 3. Fear와 Surprise — 공통 표정에서 맥락으로 확장하기

교육용 가상 사례입니다. 올라간 눈썹·커진 눈·벌어진 입과 놀라 숨을 들이키는 소리가 관찰되었다고 가정합니다.

> A: “문 좀 열어봐.”  
> 친구들: “생일 축하해!”  
> **Target · B: “헉! 너희가 올 줄은 전혀 몰랐어!”**

| 확인 순서 | 평가 내용 | Fear / Surprise | 후보 처리 |
| --- | --- | --- | --- |
| 공통 표정 확인 | 올라간 눈썹·커진 눈 → 해당 | **2 / 2** | 동률이므로 이동 보류 |
| 구분 근거 확인 | 예상 불일치·벌어진 입·놀라 숨을 들이키는 소리 → 해당 | **2 / 5** | Surprise를 다음 후보로 제안 |
| 후보 이동 | 확인한 근거를 유지 | 2 / 5 | Fear → Surprise |

## 점수와 후보 이동 규칙

1. 각 감정에 연결된 고유 요소 중 `해당`인 항목 수를 셉니다. 같은 요소를 반복 확인해도 중복 가산하지 않습니다.
2. `비해당`은 별도로 집계하며 점수에서 차감하지 않습니다. `미확인`은 아직 검토하지 않았거나 근거가 부족한 상태입니다.
3. 공통 요소 하나가 해당이면 **그 요소에 연결된 모든 감정에 동일하게 반영**합니다. 현재 화면에 보이지 않는 감정도 갱신합니다.
4. **전체 후보 중 단독 최상위이고, 현재 후보보다 해당 항목 수가 많을 때만** 이동 버튼을 활성화합니다. 동률이면 이동하지 않습니다.
5. 후보를 이동해도 기존 근거는 유지합니다. 두 후보를 구분하는 미확인 요소를 다음 검토 항목으로 제시합니다.
6. 같은 사건·대상을 평가한다는 전제에서 목표 일치/불일치, 높은/낮은 통제 가능성, 결과의 확실성/불확실성을 동시에 해당으로 둘 수 없습니다. 반대 조건을 새로 해당으로 바꾸면 기존 해당 조건을 비해당으로 바꾸고 화면에서 알립니다. 타인 원인과 상황 중심은 자동 배타 조건으로 처리하지 않습니다.

감정마다 연결된 요소 수가 달라 단순 개수 비교에 편향이 있을 수 있습니다. 반증 가중치·확률·최종 확정 기준은 이 데모에 포함되어 있지 않습니다.

## 데이터와 구현 범위

- 대화에서 정리한 인지 평가 12개와 표현·행동 단서 17개, 총 29개를 사용합니다. 원 논문이 제시한 검증된 29문항 척도라는 의미는 아닙니다.
- Anger, Frustration, Happiness·Joy, Fear, Sadness, Surprise, Disgust의 연결을 정의합니다.
- Excitement, Neutral, Other는 선택한 체크리스트에 독립 조건이 없어 순위 계산에 넣지 않습니다. 점수가 없다고 이 감정을 배제하는 것은 아닙니다.
- 인지 평가에 붙인 `[텍스트]`는 이 프로젝트의 관찰 모달리티 규칙입니다. 이론이 해당 모달리티만 사용하도록 지정했다는 의미는 아닙니다.
- 감정 모델을 호출하지 않습니다. 대화·영상·음성을 자동 분석하지 않으며, 화면의 예시와 사용자의 수동 평가를 반영합니다.
- 외부 서비스로 입력을 전송하지 않으며, 상태는 브라우저 메모리에서만 유지됩니다. 새로고침하면 예시의 시작 상태로 돌아갑니다.

## 코드 수정과 검증

| 파일 | 수정할 내용 |
| --- | --- |
| `index.html` | 메인 화면과 실습 영역 구성 |
| `assets/styles.css` | 디자인, 반응형 배치, 밝은·어두운 테마 |
| `assets/data.js` | 29개 요소, 감정별 연결, 세 가지 대화와 단계 |
| `assets/engine.js` | 점수, 동률 처리, 후보 이동, 단계 재생 |
| `assets/app.js` | 버튼 조작, 상태 갱신, 노드와 선 그리기 |
| `tests/engine.test.js` | 동률·공통 근거·후보 이동·미확인·상반 조건·세 예시 검증 |

Node.js가 있는 환경에서는 다음 명령으로 핵심 로직을 검증합니다. 브라우저 실행에는 Node.js가 필요하지 않습니다.

```sh
node --test tests/engine.test.js
```
